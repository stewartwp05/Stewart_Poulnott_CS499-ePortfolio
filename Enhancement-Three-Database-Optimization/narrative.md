For this part I focused on database stuff that was making the app run slow and could mess things up down the line. Loading the dashboard took way too long because it had to go through every single row in the table to find your weights since I didn't have indexes set up. So I added indexes on user_id and date. When I tested it with 50 entries vs just a few the speed difference was definitely noticeable. I also added foreign keys with CASCADE delete because without them if a user account got deleted their weight entries would just hang around in the database forever. Another issue was setUserGoal does a couple different database operations but they weren't wrapped in a transaction so if something crashed partway through you'd have incomplete data. And deleteWeight wasn't checking if you actually owned the entry before deleting it which seemed like a problem.
The hard part was dealing with SQLite not letting you just add foreign keys to tables that already exist. You have to create a completely new table with the foreign key built in, copy everything from the old table using INSERT INTO SELECT, drop the old table, and rename the new one. And that whole process needs to be in a transaction or you'll corrupt the database if anything fails. When I tested everything the indexes definitely sped up the queries. I tried deleting a test user and their weights got removed too which showed the foreign keys worked. The authorization thing also worked - I couldn't delete entries that weren't mine. I guess what I took away from this is databases are more complicated than just throwing data in tables. You need indexes or things get slow, and foreign keys with transactions to make sure everything stays connected right.
