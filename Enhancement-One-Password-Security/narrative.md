The artifact I enhanced is the WeightTracker Android app from CS-360 that I built during summer 2025. The problem that I corrected is that it stored passwords in plain text, which is a major security risk. I fixed this by creating a new PasswordHasher.kt file that handles the password hashing as well as other security implementations, it generates random salts using SecureRandom, hashes passwords with SHA-256, and validates that passwords meet basic requirements like being at least 8 characters with an uppercase letter and number. In DatabaseHelper.kt, I updated the database from version 3 to 4 and added a password_salt column. Instead of dropping all the tables like the old code did, I rewrote onUpgrade() to use ALTER TABLE so existing users wouldn't lose their accounts. I also created a migrateExistingPasswords() function that automatically converts old plain text passwords to hashed versions when someone updates the app. Then I modified addUser() to hash passwords before saving them and updated checkUser() to compare hashes instead of plain text.
The trickiest part was figuring out the database migration. At first I didn't realize that just adding the new column would break logins for existing test accounts since they had plain text passwords but the new code expected hashes. That's why I needed the migration function to handle the conversion automatically during the upgrade. I also learned why salts are important, they prevent attackers from using pre-made hash tables to crack multiple passwords at once. Another thing I had to figure out was converting the byte array from SHA-256 into a text string that SQLite could store. When I tested it using Database Inspector, I could see the passwords were now long random-looking hashes instead of readable text, which proved it worked.
